# factgate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A config-driven library and CLI that turns any text documents into quoted facts and rule-based decisions, with the rolescan guarantees and a repeat/held-out/compare eval.

**Architecture:** A separate package in `factgate/` (own `pyproject.toml`, tests, CI job); rolescan untouched. YAML config -> dynamic Pydantic facts model -> backend call -> quote check -> resolvers -> quote check -> rules -> result. Eval reuses the same `finish` step offline, live and on regrade.

**Tech Stack:** Python 3.11+, pydantic 2, pyyaml, httpx, typer, aiosqlite; `anthropic` extra; pytest, respx, ruff, mypy strict.

**Spec:** `docs/superpowers/specs/2026-11-07-factgate-design.md`

## Global Constraints

- Python >=3.11; package name and CLI `factgate`; version 0.1.0; MIT.
- Entry-point groups `factgate.sources`, `factgate.backends`.
- No `eval`/`exec` of config text; regexes compiled at config load.
- Every item ends as exactly one of `decided`, `filtered`, `deferred`, `error`.
- The model never sets the outcome; only `rules.decide` does.
- Quote check: whitespace collapsed, casefolded, typographic quotes/dashes/nbsp folded (rolescan `_TYPO_FOLD`); each text field a separate haystack.
- Commits use the noreply author; no personal data in examples (synthetic text only).
- Only the owner's own hackathon code may be copied; credit the team in the README.
- Same gates as rolescan: ruff (C901 12), mypy strict, pytest, vulture 80, deptry.

## Review Focus

1. An item whose text contains the quote only across two fields: must not verify (test in Task 2).
2. A model answer that is not valid against the schema (bad enum, malformed JSON): that item is `error`, the run continues (Task 5).
3. A config typo (unknown fact in a rule, unknown operator, bad regex): fails at load with the rule's name (Task 3).
4. The call ceiling hit mid-run: the rest are `deferred`, none lost, none errored (Task 5).
5. A live eval attempt that raises: `inconclusive`, never counted in the pass rate (Task 7).

### Task 2: Facts schema and the quote check

**Files:** Create `src/factgate/schema.py`, `src/factgate/verify.py`, tests `test_schema.py`, `test_verify.py`.

**Interfaces — Produces:**
- `class Fact(BaseModel, Generic[T]): value: T | None = None; quote: str = ""`.
- `FactSpec(BaseModel)`: `type: Literal["number","integer","text","bool","date","enum","list"]`, `describe: str = ""`, `values: list[str] | None` (enum), `of: <scalar type> | None` (list), `values` allowed on list-of-enum.
- `build_model(specs: dict[str, FactSpec]) -> type[BaseModel]`: each field `Fact[T]`, list facts `list[Fact[T]]` default `[]`, enum via `Literal`.
- `system_prompt(specs) -> str` (states every fact, type, description, allowed values, and that each quote must be copied verbatim, null and "" when not stated).
- `check_quotes(facts: BaseModel, item: Item) -> BaseModel` (new object): unverified scalar -> `Fact()`, unverified list element dropped; number/integer value must be among the quote's numbers (`£12,500.00` -> 12500.0; separators `,` and space removed; currency symbols ignored).

- [ ] Tests: quote spanning `subject`+`body` boundary is cleared; curly-quote and nbsp folding verifies; `"Total due: £12,500"` with 125000 cleared, with 12500 kept; enum outside values rejected by `model_validate`; list element with a bad quote dropped, good one kept; `system_prompt` mentions every fact name and enum value.
- [ ] Implement, run, commit.

### Task 3: Config and rules

**Files:** Create `src/factgate/config.py`, `src/factgate/rules.py`, tests `test_config.py`, `test_rules.py`.

**Interfaces — Produces:**
- `Condition = dict[str, Any]` of operators: `is, eq, ne, lt, le, gt, ge, in, contains, matches, stated, within_days, before_days`.
- `class Rule(BaseModel): name: str; when: dict[str, Condition]; then: str`.
- `matches(fact_value, cond: Condition, as_of: date) -> bool` — shared by rules and eval grading. Unstated value -> False except `stated: false`. On a list fact an operator is true if any element's value matches; `stated` means non-empty; `contains` on list = some element equals.
- `class Decision(BaseModel): outcome: str; rule: str | None; quotes: dict[str, str | list[str]]`.
- `decide(facts: BaseModel, rules: list[Rule], default: str, as_of: date) -> Decision` (first match wins).
- `class Config(BaseModel)`: `name, items: ItemsConfig, prefilter: Prefilter | None, facts: dict[str, FactSpec], rules: list[Rule] = [], default_outcome: str, model: ModelConfig, cache: Path | None = Path(".factgate/cache.sqlite"), resolvers: list[str] = [], dangerous: list[dict[str,str]] = []`; `load_config(path) -> Config` (relative paths resolved against the config's folder). Validation: rule naming an unknown fact, unknown operator, operator not valid for the fact type, bad regex -> error naming the rule.
- `ModelConfig`: `backend: str = "anthropic"`, `name: str`, `base_url: str | None`, `api_key_env: str | None`, `max_calls: int = 100`, `max_minutes: float = 30`, `max_concurrent: int = 4`, `max_tokens: int = 2048`, `temperature: float | None = None`.

- [ ] Tests: each operator true and false case; `within_days: 14` with `as_of` 2026-11-07 true for 2026-11-20, false for 2026-11-22 and for a past date; `before_days: 0` true for yesterday; first-match-wins; default when none; loader errors for each bad config above, message contains the rule name.
- [ ] Implement, run, commit.

### Task 4: Backends and cache

**Files:** Create `src/factgate/backends.py`, `src/factgate/cache.py`, tests `test_backends.py` (respx), `test_cache.py`.

**Interfaces — Produces:**
- `class Answer(BaseModel): raw: dict[str, Any]; input_tokens: int = 0; output_tokens: int = 0`.
- `class Backend(ABC)`: `name: ClassVar[str]`; `__init__(cfg: ModelConfig)`; `async extract(system: str, user: str, model: type[BaseModel]) -> Answer`.
- `AnthropicBackend` (`anthropic`): `messages.parse(output_format=model)`, system block with `cache_control` ephemeral; `temperature` only when set, retried once without it on a 400 that says so (rolescan rule).
- `OpenAICompatibleBackend` (`openai-compatible`): POST `{base_url}/chat/completions`, `response_format={"type":"json_schema","json_schema":{"name":"facts","schema":...,"strict":False}}`, bearer key from `api_key_env` if set; one retry after 2 s on timeout/5xx.
- `ReplayBackend` (`replay`): `ReplayBackend.from_file(path)`; answers keyed by item id (system/user ignored); missing id raises `KeyError`.
- `get_backend(cfg, replay: Path | None) -> Backend` (entry points `factgate.backends`).
- `render_user(item: Item) -> str`: `## <field>\n<text>` blocks in field order.
- `class Cache`: async ctx manager on sqlite path; `get(key) -> dict | None`, `put(key, raw: dict)`; `cache_key(item, fingerprint, backend, model) -> str`; `fingerprint(system, schema_json, max_tokens, temperature) -> str` (12 hex).

- [ ] Tests: openai-compatible request body carries the schema and parses `choices[0].message.content`; 500 then 200 retries once; replay returns the recorded raw; cache round trip; fingerprint changes with the prompt.
- [ ] Implement, run, commit.

### Task 5: Pipeline, prefilter, resolvers, output, CLI `run`/`check`/`init`

**Files:** Create `src/factgate/pipeline.py`, `src/factgate/output.py`, `src/factgate/cli.py`, `src/factgate/templates/` (starter config, 3 items, 2 cases); tests `test_pipeline.py`, `test_cli.py`.

**Interfaces — Produces:**
- `Prefilter(BaseModel): require_any: list[str] = []; exclude_any: list[str] = []` (whole-word, case-insensitive, over all fields).
- `class Result(BaseModel): id; status: Literal["decided","filtered","deferred","error"]; outcome: str | None; rule: str | None; facts: dict[str, Any]; reason: str = ""; meta: dict; raw: dict | None`.
- `finish(raw: dict, item: Item, cfg: Config, model: type[BaseModel], resolvers, as_of) -> tuple[BaseModel, Decision]`: validate -> `check_quotes` -> each resolver -> `check_quotes` -> `decide`. Used by run, offline eval, live eval and regrade.
- `load_resolvers(names: list[str]) -> list[Callable[[Item, BaseModel], BaseModel]]` (`module:function`, import error names the entry).
- `class RunStats`: calls, cache_hits, errors, deferred, input_tokens, output_tokens, seconds.
- `async run(cfg, items, backend, *, as_of: date, cache: Cache | None, record: Path | None = None) -> tuple[list[Result], RunStats]`: prefilter; cache; up to `max_calls` calls and `max_minutes`, `max_concurrent` at a time; past either -> `deferred`; 3 errors in a row -> remaining `deferred` with reason "stopped after 3 errors in a row"; an invalid answer -> that item `error`; `record` appends `{"id","raw"}` lines (the replay format).
- `write_results(results, path)` JSONL; `summary_markdown(cfg, results, stats) -> str` (counts per status, per outcome, per rule; stats).
- CLI: `factgate run CONFIG [--replay F] [--record F] [--dry] [--out F] [--as-of DATE] [--no-cache]`; `factgate check CONFIG` (prints prompt + JSON schema); `factgate init NAME` (copies templates; refuses a non-empty folder).

- [ ] Tests: prefilter `exclude_any` -> `filtered` with the term in `reason`; `max_calls: 2` over 5 items -> 2 decided, 3 deferred; a replay answer with a bad enum -> `error`, others decided; 3 consecutive backend errors -> rest deferred; second run serves from cache (calls 0); a resolver that invents an unquoted value is undone by the second quote check; `--dry` makes no call; `init` then `run --replay` on the template works.
- [ ] Implement, run, commit.

### Task 6: Eval cases, grading and offline run

**Files:** Create `src/factgate/eval/__init__.py`, `eval/cases.py`, `eval/grade.py`, `eval/pytest_helper.py`; tests `test_eval_cases.py`, `test_grade.py`.

**Interfaces — Produces:**
- `class Case(BaseModel): id; fields: dict[str,str]; expect_facts: dict[str, Condition] = {}; expect_outcome: str | None; model_facts: dict | None; tags: list[str] = []; open_defect: str = ""; as_of: date | None; heldout: bool = False`. Input form accepts `text:` as shorthand for `fields: {text: ...}` and `expect: {facts:..., outcome:...}`.
- `load_cases(paths: list[Path], cfg: Config, *, heldout: list[Path] = []) -> list[Case]`: JSONL or YAML; errors with `file:line` on bad JSON, duplicate id across files, unknown fact/operator, nothing to grade.
- `grade(case, facts, decision, cfg) -> Grade` where `Grade(BaseModel): passed: bool; fact_failures: list[str]; outcome_failure: str | None; dangerous: bool` (dangerous when `{expected: case.expect_outcome, got: decision.outcome}` is in `cfg.dangerous`).
- `offline(case, cfg, model, resolvers) -> Grade` (uses `model_facts` through `finish`).
- `pytest_cases(config_path, case_paths) -> list[pytest.param]` (xfail strict when `open_defect`).

- [ ] Tests: duplicate id across two files names both; unknown operator names file:line; outcome-only failure sets `outcome_failure` and empty `fact_failures`; dangerous flagged; `open_defect` param is strict xfail.
- [ ] Implement, run, commit.

### Task 7: Live eval: repeats, states, inconclusive, held-out, compare, regrade, report

**Files:** Create `eval/live.py`, `eval/compare.py`, `eval/report.py`; extend `cli.py` with `factgate eval run|compare|regrade`; tests `test_live.py`, `test_compare.py`.

**Interfaces — Produces:**
- `attempt outcome`: `pass | fail | inconclusive` (inconclusive = backend raised, or answer invalid).
- `case_state(outcomes: list[str]) -> str`: from the owner's `intensive.py`: pass+fail -> `flaky`; any fail -> `fail`; any inconclusive -> `inconclusive`; all pass -> `pass`.
- `async live(cases, cfg, backend, *, repeats: int, label: str) -> EvalRun` — no cache; every attempt saved with its raw answer.
- `offline_run(cases, cfg, label) -> EvalRun` (one attempt per case).
- `EvalRun(BaseModel)`: label, date, backend, model, repeats, seconds, tokens, `cases: list[CaseRun]`; `CaseRun`: id, heldout, tags, state, attempts (outcome, raw, fact_failures, outcome_failure, dangerous), `facts_changed: bool` (the model's raw facts differed between conclusive attempts).
- Metrics: `pass_at_1` = passed attempts / conclusive attempts; `pass_hat_k` = cases `pass` / cases not `inconclusive`; `wilson(successes, n) -> (lo, hi)` 95%.
- `compare(a: EvalRun, b: EvalRun) -> Comparison`: per split (visible, held-out): `fixed` (fail->pass), `broke` (pass->fail), `noise` (flaky either side, changed), `inconclusive` (either side), and the case ids of each.
- `regrade(run: EvalRun, cases, cfg) -> EvalRun` (label `<label>-regrade`, re-runs `finish` + `grade` on saved raw answers, no calls).
- `report_markdown(run, cfg) -> str`: per-split state counts, per-tag table, pass@1 and pass^k with Wilson interval stated as "Wilson 95%", inconclusive count, dangerous errors listed first, held-out cases as ids only.
- Files: `results/<label>.json`, `results/<label>.md`; compare writes `results/compare-<a>-<b>.md`.
- `readme_matches(readme: Path, run: EvalRun) -> list[str]` (missing figures).

- [ ] Tests: `case_state` table (pass,pass->pass; pass,fail->flaky; fail,fail->fail; pass,inconclusive->inconclusive; fail,inconclusive->fail); an attempt whose backend raises is inconclusive and not in pass@1's denominator; held-out ids absent from the item text in the report; compare counts fixed/broke/noise on a fixture pair; regrade of a run after a rule change flips the expected case with zero backend calls; `wilson(7, 8)` ~ (0.529, 0.978).
- [ ] Implement, run, commit.
